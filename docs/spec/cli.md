# CLI 仕様

## コマンド名

`tchart`

## 使い方

```
tchart svg      <INPUT>           [OPTIONS]
tchart png      <INPUT>           [OPTIONS]
tchart src      <FILE>            [OPTIONS]
tchart wavedrom <INPUT>           [OPTIONS]
tchart batch    <svg|png> <INPUT>... -o <DIR> [OPTIONS]
```

`source` は `src` のエイリアス。
`svg` / `png` / `src` / `wavedrom` は単一入力専用 (`<INPUT>` または `<FILE>` を 2 個以上指定するとエラー、終了コード 1)。
複数入力をまとめて処理する場合は `batch` サブコマンドを使う (`wavedrom` は現状 `batch` 非対応)。

### `-o, --output <PATH>` の解釈

- `svg` / `png` / `src` / `wavedrom` (単一): ファイルパスとして扱う。省略時は入力ファイル隣に `<STEM>.<拡張子>` を出力する。
- `batch`: ディレクトリパスとして扱う (必須)。各入力を `<DIR>/<STEM>.<拡張子>` に出力する。

`<拡張子>` は `svg` / `png` / `tc` / `json`。

#### `-` (単一ハイフン) で標準出力を指定する

`src` サブコマンドに限り、`<PATH>` が `-` (単一ハイフン) の場合は出力先をファイルではなく標準出力 (stdout) として扱う。抽出した TCML 本文をバイト列のままそのまま `stdout` に書き出す (末尾改行の有無は埋め込みデータどおり)。`stdout` への書き込みに失敗した場合 (パイプ切断など) は出力エラーとして終了コード 1 を返す。

他のサブコマンド (`svg` / `png` / `wavedrom` / `batch`) は `-o -` を stdout 指定として解釈しない。これらに `-o -` が渡された場合は通常通り `-` という名前のファイルとして扱う (本仕様で stdout モードを規定するのは `src` のみ)。

## サブコマンド

### `svg`

TCML を SVG にレンダリングする。入力は 1 個のみ。

| 引数/オプション | 説明 | デフォルト |
|-----------------|------|------------|
| `<INPUT>` | 入力 TCML ファイル (.tc) | 必須 |
| `-o, --output <FILE>` | 出力ファイルパス | 入力隣に `<STEM>.svg` |
| `--font <FILE>` | デフォルトフォントファイルパス (詳細は §フォント管理) | システムフォント自動検出 |
| `--font-size <SIZE>` | フォントサイズ (px)。`> 0` の有限値のみ受理する (0 / 負値 / 非有限値は引数バリデーションエラーで終了コード 1) | `12.0` |
| `-h, --help` | ヘルプ表示 | |
| `-V, --version` | バージョン表示 | |

### `png`

TCML を PNG にラスタライズする。入力は 1 個のみ。
内部で SVG を生成し、`resvg` で PNG に変換する。
PNG の iTXt チャンク (UTF-8) にキー `tchart-source` で元の TCML テキストをそのまま (エスケープなし) 埋め込む。tEXt ではなく iTXt を使うのは TCML 中の非 ASCII 文字 (信号名や `@title` の日本語等) を埋め込み可能にするため。

| 引数/オプション | 説明 | デフォルト |
|-----------------|------|------------|
| `<INPUT>` | 入力 TCML ファイル (.tc) | 必須 |
| `-o, --output <FILE>` | 出力ファイルパス | 入力隣に `<STEM>.png` |
| `--font <FILE>` | デフォルトフォントファイルパス | システムフォント自動検出 |
| `--font-size <SIZE>` | フォントサイズ (px)。`> 0` の有限値のみ受理する (0 / 負値 / 非有限値は引数バリデーションエラーで終了コード 1) | `12.0` |
| `-h, --help` | ヘルプ表示 | |

ラスタライズ解像度は SVG の `width`/`height` に等倍 (1px = 1px)。
フォントは §フォント管理 で解決したフォント群を `fontdb` に登録して描画する。

### `src` (alias: `source`)

SVG / PNG ファイルに埋め込まれた TCML ソースを取り出す。入力は 1 個のみ。

| 引数/オプション | 説明 | デフォルト |
|-----------------|------|------------|
| `<FILE>` | 入力 SVG または PNG ファイル | 必須 |
| `-o, --output <FILE>` | 出力ファイルパス。`-` (単一ハイフン) を指定すると標準出力に書き出す (§`-` (単一ハイフン) で標準出力を指定する) | 入力隣に `<STEM>.tc` |

- SVG: `<tchart:source>...</tchart:source>` 要素を検索し、XML アンエスケープ (`&lt;` → `<` 等) して書き出す
- PNG: iTXt チャンクからキー `tchart-source` を検索して書き出す (互換のため tEXt も読めれば良いが、新規書き込みは常に iTXt)
- 入力に該当データがない場合は終了コード 1 (入力エラーに統合)。stderr に「埋め込み TCML が見つかりません」等の理由を出力する。区別したい場合は stderr を grep する

### `wavedrom`

TCML を [WaveDrom (WaveJSON)](https://wavedrom.com/tutorial.html) 形式の strict JSON に変換する。入力は 1 個のみ。
変換セマンティクス (要素マッピング・period 計算・矢印エンコード・落とす要素一覧) は [`wavedrom.md`](wavedrom.md) を参照。

| 引数/オプション | 説明 | デフォルト |
|-----------------|------|------------|
| `<INPUT>` | 入力 TCML ファイル (.tc) | 必須 |
| `-o, --output <FILE>` | 出力ファイルパス | 入力隣に `<STEM>.json` |
| `-q, --quiet` | 警告を stderr に出さない | off (警告出力する) |
| `-h, --help` | ヘルプ表示 | |

- 出力は UTF-8 strict JSON (コメント・末尾カンマなし)。
- フォント関連オプション (`--font`, `--font-size`) は受け付けない (WaveDrom 出力にフォント情報は含まれない)。
- 警告 (`step` の round、アンカー数超過) は stderr に出力する。終了コードには影響しない (`wavedrom.md` §警告)。
- `--quiet` 指定時は `wavedrom.md` §警告 のすべての警告 (`step` round、アンカー数超過、`@title` 2 個目以降欠落、等) を stderr に出さない。終了コードへの影響はない。

### `batch`

複数の TCML 入力をまとめて並列処理する。出力フォーマットを第 1 引数で明示し、`-o <DIR>` で出力先ディレクトリを必須指定する。

| 引数/オプション | 説明 | デフォルト |
|-----------------|------|------------|
| `<svg\|png>` | 出力フォーマット | 必須 |
| `<INPUT>...` | 入力 TCML ファイル (.tc)。1 個以上 | 必須 |
| `-o, --output <DIR>` | 出力先ディレクトリ。各入力を `<DIR>/<STEM>.<svg\|png>` に出力 | **必須** |
| `--font <FILE>` | デフォルトフォントファイルパス (詳細は §フォント管理) | システムフォント自動検出 |
| `--font-size <SIZE>` | フォントサイズ (px)。`> 0` の有限値のみ受理する (0 / 負値 / 非有限値は引数バリデーションエラーで終了コード 1) | `12.0` |
| `-h, --help` | ヘルプ表示 | |

各入力は独立ワーカで並列にパース・レンダリングされ、フォントキャッシュは全入力で共有される (§並列ワーカと共有フォントキャッシュ)。
`<DIR>` が存在しない場合は作成する。出力ファイル名衝突 (同名 STEM 入力が複数) は終了コード 3。

## 使用例

```bash
# SVG 出力 (入力隣に chart.svg)
tchart svg chart.tc

# 出力先を指定
tchart svg chart.tc -o output.svg

# PNG 出力
tchart png chart.tc                # → chart.png
tchart png chart.tc -o out.png

# 複数まとめて処理
tchart batch svg foo.tc bar.tc baz.tc -o out/
tchart batch png *.tc              -o build/

# 埋め込まれた TCML を取り出す
tchart src chart.svg -o chart.tc
tchart src chart.png

# WaveDrom JSON に変換
tchart wavedrom chart.tc            # → chart.json
tchart wavedrom chart.tc -o out.json
```

## フォント管理

### 絶対条件 (MUST)

- CLI プロセス内でフォントは **グローバルに 1 箇所で管理** する
- 同一フォントの **多重読込みを禁止** する。一度ロードしたフォントはプロセス終了まで再利用する
- `batch` サブコマンドではフォントキャッシュを全入力で共有する
- 入力ごとの「パース → フォント取得 → レンダリング → 書き出し → 破棄」は独立ワーカで並列実行し、ステージ間の大域同期点を置かない (§並列ワーカと共有フォントキャッシュ)
- レイアウト測定 (`FontMetrics`) で使ったフォントと PNG ラスタライズで `fontdb` に登録するフォントは **同一実体を参照** する
- テスト用の観測点 (load カウンタ・ロード済みフォント一覧取得など) は `#[cfg(test)]` で隔離し、リリースビルドに含めない。クレート外から観測が必要な項目は `#[cfg(target_os = "...")]` 等で OS を切り分け、本番コードに観測専用 API を漏らさない

### デフォルトフォント

`--font` / `TCHART_FONT` / 自動検出で 1 本の TTF/OTF を「デフォルトフォント」として決定する。
デフォルトフォントは TCML 中で family が未指定または解決不能な場合のフォールバックであり、
**「唯一のフォント」ではない**。

解決順:

1. `--font` オプションで指定されたファイル
2. `TCHART_FONT` 環境変数で指定されたファイル
3. OS のデフォルトフォントを自動検出
   - Linux: `fc-match` または `/usr/share/fonts/` 配下の固定候補
   - macOS: `/System/Library/Fonts` / `/Library/Fonts` を走査
   - Windows: `C:\Windows\Fonts\` を走査

すべて失敗した場合は終了コード 4 でエラー終了する。

### family 解決

TCML の `@font` で指定された family (CSV による複数指定を含む) と、
`sans-serif` などの CSS ジェネリックは CLI が以下の経路で実フォントに解決する。

- Linux: `fc-match -f '%{file}'` でパス取得
- macOS: `/System/Library/Fonts` / `/Library/Fonts` を走査
- Windows: `C:\Windows\Fonts\` を走査

解決に失敗した family はデフォルトフォントにフォールバックし、stderr に警告を 1 行出す
(終了コードには影響しない)。CSV 指定は左から順に試行し、**最初に解決できた候補のみがロード対象となる**。それより右側の候補は解決もロードも行わない。

### 並列ワーカと共有フォントキャッシュ

`batch` サブコマンドは入力ファイルごとに「パース → そのドキュメントが必要とするフォントの取得 → レンダリング → 出力書き出し → ドキュメント破棄」を独立したワーカで並列実行する。ステージ間に大域的な同期点を置かない。各入力は他の入力の進捗 (パース完了・フォントロード完了など) に依存せず最後まで進む。

これによりピークメモリは入力数 N ではなく、**並列度 W × 1 ドキュメントの最大サイズ + 既ロード済みフォント** でバウンドされる。N が極端に大きい (CI/CD への敵対的入力など) 場合でも `Vec<ChartDocument>` を全件保持しない。

並列度は実装が論理コア数を上限に決定する。並列実装機構 (スレッド方式・ライブラリ選択) は実装の裁量に委ねる。利用者向けの並列度オプション (例: `--jobs`) は性能要件が明確になるまで導入しない。

#### 共有フォントキャッシュ

フォントキャッシュは全ワーカで 1 つを共有する。論理的には「フォント識別キー → 遅延初期化セル<FontData>」のマップであり、以下の性質を満たす。

- マップへのキー登録は短い書き込みロックで即座に終わる。登録時点でセルは空 (まだロード中でない) でよい。読み取りは読み込みロックで並列に行える。マップ全体に対する長時間ロックは発生しない。
- 各セルは初回参照時にフォントをロードして格納する遅延初期化セル (`std::sync::OnceLock` 同等のセマンティクス)。同一セルを複数ワーカが同時参照しても、ロードは 1 回しか発生しない。
- フォント X のロード中にフォント Y を必要とするワーカが発生した場合、ワーカは Y のセルを使ってフォント Y のロードを並行に進められる。X と Y のロードはセルが別なので干渉しない。
- フォント X を必要としないワーカは X のセルでブロックされない。

各ワーカはパースを終え必要 family を確定したあと、まず共有キャッシュを読み込みロックで参照する。ヒットすればそのフォントの参照を取得して即座にレンダリングへ進む。ミスした場合のみ短い書き込みロックでセルを挿入し、`get_or_init` 相当でロード待ちに入る。

#### CSV と解決の挙動

各 `@font` ディレクティブの CSV はワーカ内で左から順に解決され、**最初に解決できた候補のみ**がロード対象として確定する (§family 解決)。それより右側の候補は解決もロードも行わない。解決済み候補が既に共有キャッシュに存在すれば参照取得のみで終わる。

解決失敗時はデフォルトフォントにフォールバックし、stderr に警告を 1 行出力する。同一 family の警告は CLI プロセス全体で 1 回のみ。

#### 単一サブコマンドの挙動

`svg` / `png` の単一サブコマンドは「並列ワーカ数 1、入力 1 件」の縮退として動作する。共有キャッシュは存在するがエントリは最終的に 1 ドキュメント分のみ。

`src` サブコマンドはフォント不要のため共有キャッシュを使用しない。各 `<FILE>` を独立ワーカで並列に処理する。

### PNG ラスタライズ (`fontdb`) 統合

PNG ラスタライズ時には、family 解決で得たすべてのフォントを `fontdb` に登録する。
CSS ジェネリック (`sans-serif` / `serif` / `monospace` / `cursive` / `fantasy`) は、
それぞれ family 解決で得た結果が存在すればそれを、無ければデフォルトフォントの
family 名を割り当てる。

これにより SVG 中の `font-family` (実 family 名/ジェネリック名いずれも) が
レイアウトで使ったフォントと一致して描画される。

## パースエラー出力形式

`svg` / `png` / `wavedrom` / `batch` のいずれでも、TCML パースエラー (終了コード 2) を `stderr` に出すときは以下の固定フォーマットに従う。
ファイルエラー (1) / 出力エラー (3) / フォントエラー (4) は対象外で、これらは現状の 1 行メッセージのまま変えない。

### エラー文言の言語

エラー文言 (`error:` 本文) は **英語固定** とする。
日本語や他言語への i18n は行わない。rustc / cargo / clippy と揃え、`grep` / CI ログ / Issue 検索で扱いやすい形に保つ。

### 1 件のエラーの出力例

```
error: cannot parse "xyz" as a number for @step
 --> sample.tc:3:7
3 | @step xyz
  |       ^^^
```

### 構成要素

1. **error 行** — `error: <要因の短い説明 (英語)>` を 1 行目に出す。文末にピリオドは付けない。
2. **位置行** — ` --> <FILE>:<LINE>:<COL>` の形式。`<FILE>` は入力ファイルパス。標準入力経由の場合は `<stdin>`。`<LINE>` / `<COL>` は 1 始まり。
3. **スニペット** — 該当行をそのまま 1 行出す。タブは 4 スペースに展開する (列番号もこの展開後の桁を指す)。前後に最大 80 桁を超えるときは省略して `…` を末尾に置いてもよい (実装裁量)。
4. **キャレット行** — スニペット直下に、`length >= 1` のときは `^` を `length` 文字分連続させ、`length == 0` のときは `^` 1 文字を当該列に置く。キャレット行の右側に補足メッセージは付けない。

左カラムの `|` の桁位置は揃える (行番号桁を見て調整する)。`|` の左側の数字は当該行の `<LINE>` を 10 進で出す。
スニペット行とキャレット行の上下の空白行 (左カラム `|` のみ) は付けない (最小フォーマット維持のため)。

### 複数エラーがあるとき

可能であれば全件をこのフォーマットで連結して出力する (各エントリは空行で区切る)。
最低保証として「最初の 1 件はこのフォーマットで出す」ことを必須とする。残りを要約的に出すか省略するかは実装裁量で、その場合は最後に `error: aborting due to <N> previous errors` のような件数行を 1 行で添える (rustc に倣う)。

### 入力別の `error:` 文言

各不正入力に対して CLI が出すべき具体的な文言は本仕様の規定対象外 (実装の責務)。
入力別の期待挙動 (column / length / メッセージに含めるトークン等) は [`docs/tests/parser-errors.feature.md`](../tests/parser-errors.feature.md) で観察可能な振る舞いとして固定する。

## 終了コード

| コード | 意味 |
|--------|------|
| 0 | 正常終了 |
| 1 | 入力ファイルエラー (ファイルが存在しない、`src` で埋め込みデータなし、`src` 入力が SVG/PNG として不正な形式等、入力側の問題全般) |
| 2 | パースエラー (TCML 文法エラー) |
| 3 | 出力エラー (ファイル書き込み失敗等) |
| 4 | フォントエラー |
